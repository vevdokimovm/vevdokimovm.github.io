# ADR-002 — Десять ролей вместо четырёх, с честной пометкой опоры

**Статус:** принято · 2026-08-28 · v1.1.0

## Контекст

ADR-001 (16.08.2026) держал ровно четыре роли по прямому принципу: «роль без
опоры превращает страницу из паспорта в перечень пожеланий». Владелец
28.08.2026 попросил добавить роли под остальные направления IT (Frontend,
Go, Designer, Manager, Product, Founder/CEO) явно, зная про этот принцип —
он был назван прямо перед запросом.

## Решение

Добавлены шесть ролей. Три реально подкреплены новым, появившимся уже после
ADR-001 материалом:

- **Frontend** — React/TypeScript-фронтенды, собранные за последние недели
  (интерактивное древо на 148 персон, дашборд на Recharts), реального опыта
  больше, чем было на момент ADR-001.
- **Product** — FINPILOT прочитан как продуктовый кейс: своё исследование
  на 385 респондентов, конкурентный анализ, четыре эпохи релизов.
- **Manager** — онбординг троих стажёров в BeeSchool (уже был в `experience`,
  просто не был вынесен отдельной ролью) плюс организация единого релизного
  процесса на 49 репозиториев.

Три добавлены при полном отсутствии реальной опоры — **Go, Designer,
Founder/CEO** — по прямому решению владельца после того, как ему явно
названо, что опоры нет. Принцип ADR-001 не отменён: вместо «опоры нет →
роли нет» применена **честная пометка**. Каждая из трёх ролей содержит
прямую оговорку в `summary` («честно: опыта нет», «юрлица нет, найма нет»)
и метрику `0` там, где нечего засчитать (Go: «0 проектов на Go»). Страница
не выдаёт желаемое за действительное — она говорит правду о том, что
подкреплено, и правду о том, что нет.

## Побочная находка

Проверка ссылок перед добавлением ролей нашла, что **5 из 7** карточек
проектов вели на 404: `bron-kerbosch`, `health-report-generator`,
`TG-bot-for-finances`, `Web-To-Do-List`, `Parser-hhru-vacancies` — все
удалены с GitHub в ходе более ранней чистки старых студенческих реп,
`data/profile.json` не был обновлён вслед за этим. Убраны из `projects{}`
и из `projects[]` каждой роли. Добавлен `algosite` (`algorithms-site`,
живая публичная репа) под роль Frontend.

## Следствия

Принцип «роль без опоры не появляется молча» заменён на «роль без опоры
появляется, но не молчит об этом» — решение владельца, не техническое.
Следующая правка контента (`data/profile.json`) наследует этот прецедент:
если опоры под ролью действительно нет, оговорка в `summary` обязательна,
не опциональна.
